## High‑level architecture

- **FastMCP server** – The project defines a FastMCP server named `weather-server` (see `.claude/settings.json`). The server is instantiated in `src/servers/weather_mcp.py` with `FastMCP("weather-server")` and registers a single tool:
  - `get_weather(city: str, api_key: Optional[str] = None) -> Dict[str, Any]`
    - Fetches current weather data from the OpenWeatherMap *Current Weather Data* endpoint.
    - Reads the API key from the environment variable `OPEN_WEA​THER_MAP_API_KEY` (populated via `.env`).
- **Environment handling** – `dotenv.load_dotenv()` loads the `.env` file at runtime. The file contains the secret API key and must never be committed.
- **Dependencies** – Managed with **uv** (see `uv.lock`). Core runtime deps are `fastmcp`, `pydantic`, `pydotenv`, and `ruff` for linting.

## Tips for future Claude Code instances

- **Do not commit the `.env` file** – it contains the OpenWeatherMap API key. The repository’s `.gitignore` already excludes it.
- The FastMCP server definition lives in `src/servers/weather_mcp.py`. If additional tools are added, register them with `@mcp.tool()` in the same module.
- When extending the project, keep the server name (`weather-server`) consistent with the entry in `.claude/settings.json`; otherwise Claude Code will be unable to locate the MCP endpoint.
- Use `uv` for all Python‑related tasks to stay consistent with the lock file and avoid version drift.
- For any new CLI entry‑points, follow the pattern used in the `if __name__ == "__main__":` block of `src/servers/weather_mcp.py`.
